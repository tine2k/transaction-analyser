## 3. Validating a Row

- [x] 3.1 Parse `Date` and `Value date` in `DD.MM.YYYY` form into ISO calendar dates without constructing a JavaScript `Date` — verify with a temporary fixture holding `25.09.2026` and `02.03.2026`/`01.03.2026`, confirming the stored values are `2026-09-25`, `2026-03-02`, and `2026-03-01`, and confirming a value date before its booking date is accepted, per the "Dates are read as day, month, year" requirement
- [x] 3.2 Reject a date that is not two digits, a dot, two digits, a dot, four digits, and a date whose day, month, or year does not exist on the calendar — verify with temporary fixtures for `31.02.2026`, `2026-09-25`, `5.9.2026`, and `25.13.2026`, confirming each is reported as an invalid row with a reason naming the expected day-month-year order, per the "A date that does not exist is rejected" and "A date in any other order is rejected" scenarios
- [x] 3.3 Normalise the `Amount` field textually — strip whitespace, remove a period used as a thousands separator, replace the comma with a period — and validate the result against a number pattern, keeping the value as a string throughout — verify with temporary fixtures for `-33,61`, `250,00`, `-1.234,56`, `0,01`, and `-33.61 EUR`, confirming the first four produce exactly `-33.61`, `250.00`, `-1234.56`, and `0.01` as strings and the last is reported as invalid, per design.md D3
- [x] 3.4 Reject an amount of `0,00` as an invalid row naming the zero amount as the reason — verify with a temporary fixture, confirming the row is reported before any write is attempted rather than relying on the database's `CHECK (amount <> 0)`, per the "A zero amount is rejected before any write" scenario
- [x] 3.5 Accept only `EUR` in the `Currency` column and discard it, rejecting `USD`, `CHF`, and an empty value with the found currency named in the message — verify with a temporary fixture holding all three, confirming each is reported as an invalid row and that no foreign-currency amount is converted or stored, per the "Only EUR is accepted" requirement
- [x] 3.6 Reject a row whose `Purpose` or `Name` is empty after trimming, and reject a row whose field count is not nine with the found count named in the message — verify with temporary fixtures for an empty `Name`, an empty `Purpose`, an eight-field row, and a ten-field row, confirming each is reported as invalid, per design.md D4
- [x] 3.7 Collect every invalid row rather than stopping at the first, and report each with its line number and reason — verify with a temporary fixture holding five rows invalid for five different reasons, confirming all five are reported and that the process reaches the end of the file, per the "Every invalid row is reported, not just the first" scenario
- [x] 3.8 Report a file that holds the header and no data row as holding no transaction, writing no row and reporting no error — verify with a header-only fixture, confirming a zero exit status and no connection attempt, per the "A file with no data rows imports nothing" scenario
